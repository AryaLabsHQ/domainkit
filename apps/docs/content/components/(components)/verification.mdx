`Verify.Status` renders the readiness a `Verify` controller observed: the overall state, the
per-requirement evidence, and the next check.

## What it separates

Provider evidence and public DNS evidence stay apart, because a record can exist at the provider and
still be missing from a resolver. Each entry names its source, carries the values that source
returned, and, when the requirement is not satisfied, a detail explaining why.

`Verify.Evidence` renders that breakdown on its own, inside a popover by default.

## Parts

| Part                   | Renders                                               |
| ---------------------- | ----------------------------------------------------- |
| `Verify.Status`        | The overall state, with the evidence behind a popover |
| `Verify.Evidence`      | The per-requirement evidence table                    |
| `Verify.ObserveAction` | A button that observes again now                      |
| `Verify.Outcome`       | The last failure, as a sentence from the catalog      |

## Polling

The controller observes on mount and then follows the readiness row's own `nextCheckAt` while it is
mounted, so a pending domain backs off on its own schedule. Pass `polling: false` to observe only
when the customer asks.
