## What it renders

The connect form is built from the snapshot, not from hard-coded provider names. Each provider
carries its auth methods, and each method its label, docs URL, and token fields, so a new provider
appears in the dialog without a UI change.

When the transport declares `connection.discover`, the flow asks on mount which of the customer's
existing connections already reaches the domain and offers that first. A discovery failure is
silent: the provider list still renders.

## Parts

| Part              | Renders                                                       |
| ----------------- | ------------------------------------------------------------- |
| `Connect.Card`    | The connected provider, with detach and disconnect            |
| `Connect.Dialog`  | The connect surface, with a `render` prop for your own dialog |
| `Connect.Form`    | The method picker and token fields, without the dialog        |
| `Connect.Status`  | One line of what the connection is doing                      |
| `Connect.Outcome` | The last failure, as an [outcome](/components/outcome)        |

## Where the customer comes back to

An interactive method returns the customer to the page they started from, read when they connect
rather than when the flow renders. `returnTo` names a different destination, and `null` leaves the
server's `defaultReturnTo` in charge.

## Read-only

Connecting is a write, so the whole surface goes rather than a disabled trigger: the slot renders
the catalog's `notConnected` sentence instead.

## Composing it yourself

`Connect.useController({ domain })` returns the state and the five commands. See
[controllers](/docs/react/controllers).
