title: Domain flow
description: The whole custom-domain lifecycle for one domain, from connecting a provider through reviewing the plan, applying it, observing DNS, and cleaning up.
---

`Domain.Flow` is the complete flow. It composes the four controllers, renders three slots with
defaults, and shows only the capability groups the transport declares.

Once the domain is attached with nothing applied to it yet, the flow plans, and the plan lands in
the records table: every row says whether it will be added, is already there, or is in the way, and
the header carries the one action that adds them. No review dialog opens. `Provision.Dialog` stays
exported for a host that wants the standalone surface.

## Props

| Prop           | Type                               | Required | Means                                       |
| -------------- | ---------------------------------- | -------- | ------------------------------------------- |
| `domain`       | `string`                           | yes      | The customer domain this flow is for        |
| `requirements` | `ReadonlyArray<DnsRecord.Model>`   | yes      | The records your product needs              |
| `slots`        | `Domain.Slots`                     | no       | Replace one part of the flow, keep the rest |
| `onApplied`    | `(receipt: Receipt.Model) => void` | no       | Fires once an apply produced a receipt      |
| `onCleaned`    | `(receipt: Receipt.Model) => void` | no       | Fires once a cleanup produced a receipt     |
| `returnTo`     | `string \| null`                   | no       | Where an interactive provider returns       |
| `readOnly`     | `boolean`                          | no       | Render without the controls that change it  |

It also takes the composition props every part takes: `className`, `style`, and `render`.

## The member view

`readOnly` removes every control that would start a write rather than disabling it. Status, records,
and evidence stay, and so does checking DNS, because observing reads the world rather than changing
the domain. Toggle it in the preview controls above.

## What it decides, and what it does not

The flow decides the order of the steps and the default presentation. It does not decide identity,
tenancy, consent, audit policy, or product readiness: it renders what the transport answers and
reports finished steps through `onEvent` on `DomainKit.Root`.
