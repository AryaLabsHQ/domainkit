The DomainKit registry contains React components for DNS interfaces. Add the files to your
application with the shadcn CLI, then own their markup, styling, and behavior.

The registry follows shadcn conventions. Your project needs an initialized `components.json`;
required shadcn primitives are listed as `registryDependencies`, and the CLI installs those for you.
Components accept native element props and `className`, use `data-slot` attributes, and inherit your
shadcn color, radius, and focus-ring tokens.

## The flow

The flow items install into `components/domainkit/` and are written against `@domainkit/react` and
your own kit, on the Base UI idiom: components take `render`, not `asChild`. They are the one styled
path DomainKit ships.

## The display components

These install into the configured `ui` alias, take plain props, and import no DomainKit runtime: no
`domainkit`, no Effect, no transport, no provider client. They suit a product that already has its
own state and only needs the surface.

## Install from the registry

Install one item or several items directly into your application:

```package-install
npx shadcn@latest add https://domain-kit.dev/r/domain-flow.json
```

The source is yours after you copy it. Change its classes, icons, and layout to fit your design
system. Keep credentials, authenticated routes, storage, and readiness rules outside it: the
behaviour behind the flow still runs through the transport your server owns.

The [components overview](/components) lists every item with a preview, and the
[registry guide](/docs/react/registry) covers where the boundary sits between a copied file and the
transport behind it.
