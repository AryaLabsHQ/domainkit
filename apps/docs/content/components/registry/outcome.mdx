`outcome` renders a `DomainKit.Error`. The title and the description come from the error's reason
through the catalog, so nothing renders a tag, a status literal, or a reason name.

<Component path="registry/outcome" />

## Installation

```package-install
npx shadcn@latest add https://domain-kit.dev/r/outcome.json
```

## Usage

```tsx
<Outcome
  context={{ domain, provider: "Cloudflare" }}
  error={state._tag === "Failure" ? state.error : null}
  onRetry={controller.retry}
/>
```

The reason alone cannot name the provider a customer typed a token for, so the surface supplies it
in `context`.

## API

| Prop      | Type                      | Required | Description                                   |
| --------- | ------------------------- | -------- | --------------------------------------------- |
| `error`   | `DomainKit.Error \| null` | yes      | The failure, or `null` when the step is fine. |
| `context` | `Messages.OutcomeContext` | no       | The provider and domain the words may name.   |
| `onRetry` | `(() => void) \| null`    | no       | The retry to offer, or none.                  |
| `layout`  | `"card" \| "inline"`      | no       | A panel of its own, or a line under a field.  |

## Boundary

The same file exports `CallbackRecoveryAlert`, used by the
[domain flow](/components/registry/domain-flow) and [domain field](/components/registry/domain-field).
It reads `Connect.useRecovery()` and accepts `providers`, `onRetry(input: Connect.ConnectInput)`,
and optional `disabled`. The catalog supplies the message and action labels. Cancellation and
`restart` can offer an available interactive method; `inspect` only gives account inspection
guidance. Dismiss clears the URL hint without navigation. Root read-only and connection capability
checks suppress retry, and `disabled` blocks it while a command is in progress.

A retry is a write, so a read-only surface passes `null` and the outcome offers none. What is
retryable is on the error itself: read `isRetryable` rather than matching on words.
