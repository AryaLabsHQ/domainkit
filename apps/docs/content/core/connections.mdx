`Connection.start` accepts either an interactive provider flow or a token method. Interactive starts return `Redirect`; token methods normally return `Connected`. `Connection.complete` consumes a short-lived continuation exactly once.

```text
host session
  -> Connection.start
  -> provider consent or token validation
  -> host-owned lifecycle repository
  -> authorization aggregate + encrypted credential reference + owner grant
```

## Host ownership

DomainKit defines the lifecycle contract but does not choose your infrastructure. Your application supplies:

- callback routes and authenticated sessions;
- a durable `AuthorizationLifecycle.Repository`;
- secret storage or encryption at rest;
- a short-lived, one-time `ContinuationStore`;
- consent and audit records tied to your own user and organization IDs.

The repository boundary is intentionally aggregate-shaped so SQL applications can use one transaction and split database/vault applications can implement a recoverable saga.

## Reuse an account

After proving that the same provider authorization owns another domain and obtaining the owner's consent, extend the existing grant without another provider round trip:

```ts
const aggregate = await Connection.extend({
  connectionId,
  grant: {
    _tag: "domains",
    domains: [DomainName.parse("mail.example.com")],
  },
  ownerId,
  repository,
});
```

`Connection.removeDomain` removes one domain binding while preserving DNS. Provider revocation happens only when the last binding is removed, and durable state remains retryable until the provider confirms revocation.

<Callout type="warning" title="Continuation storage">
  Losing an OAuth continuation may require the user to restart consent. Losing a durable
  authorization aggregate or receipt must not be possible through cache eviction.
</Callout>
