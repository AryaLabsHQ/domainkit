Three rows carry a customer's provider access, and each answers a different question.

```text
authorization   the credential, sealed, plus the provider account context
     |
connection      the principal-facing handle over one authorization
     |
attachment      one domain bound to one connection and one exact zone
```

One authorization can back several connections, and one connection can serve several domains.
DomainKit never deduplicates by provider account: a second organization connecting the same
provider account gets its own authorization from its own fresh proof.

## Connecting

A token method finishes in one call. OAuth and marketplace installs answer with a redirect and
finish at the callback.

<Snippet file="examples/core/connections.ts" region="interactive" title="An interactive method" />

`Connect.start` answers one of three things:

| `Started`           | Means                                                                |
| ------------------- | -------------------------------------------------------------------- |
| `Connected`         | The connection exists, and the domain is attached when one was given |
| `Redirect`          | Send the customer to `authorizationUrl`; the callback finishes it    |
| `SelectionRequired` | The credential reaches several matching zones; pick one and attach   |

The continuation created by `start` is spent exactly once, so a replayed callback fails `NotFound`
rather than connecting twice.

## Reusing a connection

The second domain on a provider the customer already connected should not ask them to connect
again. `Connect.discover` resolves the domain's authoritative nameservers, lists the zones each of
the principal's connections can reach, and answers which one serves it.

<Snippet file="examples/core/connections.ts" region="discover" title="Skipping the connect step" />

The closest zone wins. When several connections hold that zone, a connection whose reported
nameservers cover every authoritative nameserver wins; otherwise the caller selects.

When no connection reaches the domain, `NotFound` carries the authoritative nameservers and `host`:
the one registered provider whose declared nameserver suffixes cover every one of them, matched on
trailing labels and ignoring case. Cloudflare declares `ns.cloudflare.com` and Vercel declares
`vercel-dns.com`, so a connect screen can name the provider that already serves the domain before
the customer picks one. `host` is `null` when no provider matches or more than one does.

## Attaching

<Snippet file="examples/core/connections.ts" region="attach" title="Binding a domain to a zone" />

An attachment is exact: one domain, one connection, one zone, and the provider identity that
addresses it. Every session handed to planning, applying, or observing is re-checked against the
provider, so a zone the credential can no longer reach fails `NotFound` instead of writing
somewhere else.

## Releasing

<Snippet file="examples/core/connections.ts" region="release" title="Detach and disconnect" />

Detaching forgets the domain and leaves the records in DNS. Plan a
[cleanup](/docs/core/cleanup) first when the records should go.

Disconnecting detaches every domain and revokes the credential at the provider where the method
supports it. Revocation is two-phase: the row is marked pending, the provider is called outside any
transaction, and only then is the row removed. A failure in between leaves a row that recovery
finishes on the next connect or disconnect.

## Keeping the credential alive

`Connect.refresh` runs automatically before provider use, ten minutes before expiry by default, and
single-flights through the storage lock so two requests never refresh at once. It answers `current`,
`refreshed`, or `reconnect`.

An access token expiring is not the authorization expiring: a credential with a refresh token stays
usable. A credential the provider will no longer refresh surfaces as the `Reconnect` reason, and the
host asks the customer to connect again.

`Connect.Policy` sets `refreshBeforeMs`, the continuation lifetime, and `allowReuse`, which decides
whether one of an owner's connections may serve a given domain.

Setting up DNS through a provider's own template protocol instead is
[Domain Connect](/docs/core/domain-connect), which DomainKit does not implement.
