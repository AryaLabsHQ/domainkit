A host writes one service and mounts one route group. Everything else, including provider callbacks
and the error-to-status table, comes with them.

## Prerequisites

- `domainkit` and `effect` installed, Node.js 24.10 or newer.
- A `Storage` implementation. [Persistence and custody](/docs/guides/storage) covers the options.
- A 32-byte custody key in `DOMAINKIT_CUSTODY_KEY`, or a KMS.
- A session credential your app already issues, readable from a cookie.

## Compose the layer

`DomainKit.layer({ providers })` provides every lifecycle service and requires `Storage` and
`Custody` beneath it.

<Snippet file="examples/storage/postgres.ts" region="wire" title="The lifecycle layer" />

Compose `Storage` with `provideMerge`, not `provide`: the route handlers read attempts and receipts
straight from it.

## Write Identity

`Server.Identity` maps a request to a `Principal`. It is the only service you implement.

<Snippet file="examples/server/mount.ts" region="identity" title="Identity" />

Two rules make this safe:

- **Verify a credential you issued, then look the tenant up yourself.** A request never names its
  own `ownerId`. Every stored row is scoped by whatever this returns, so a request you cannot
  attribute must fail closed.
- **Read it from a cookie.** `/callback/:provider` is a top-level navigation the provider sends the
  browser on, so only what the browser attaches by itself arrives with it. A header-only scheme
  works until the first interactive connection and then fails at the last step.

`Identity` takes an optional `authorize`, which runs after `principal` with the name of the route
being served. Use it when reads and writes belong to different roles.

<Snippet file="examples/server/mount.ts" region="authorize" title="Splitting reads from writes" />

Leave it out when your own middleware already gates the mount: without it every authenticated
principal reaches every route.

## Mount the group

<Snippet file="examples/server/mount.ts" region="mount" title="Adding the group to your API" />

`Server.group` covers the whole lifecycle in seventeen endpoints. It declares no path of its own, so
one prefix moves every route and the callback URL follows it.

`GET /zones` is the read a picker needs: every zone the principal's connections reach, how each
connection stands, and the provider catalog. Members add domains, so it belongs with the reads in
`authorize`; `start` stays a write.

<Snippet file="examples/server/mount.ts" region="prefix" title="Mounting elsewhere" />

Hosts that are not on Effect's HTTP stack take the same group as one `fetch` handler.

<Snippet file="examples/server/mount.ts" region="web-handler" title="The Web handler" />

Mount `handler` on a catch-all route under the prefix, and call `dispose` when the process shuts
down. Hono, Next.js App Router, and TanStack Start all take a Web handler directly.

## Handle the callback

An interactive connection ends at `/callback/:provider`. DomainKit spends the continuation, stores
the connection, and redirects the customer.

The destination is the `returnTo` the flow was started with, or `defaultReturnTo`. It is resolved
against the callback URL and must land on its origin, so neither the provider nor a crafted
`returnTo` can steer the customer off your application. `returnTo` is not a declared callback query
parameter, so the provider cannot set it at all.

By default the callback URL is the request's own origin plus the prefix the group is mounted at. An
edge that rewrites `Host` leaves that pointing somewhere the browser never reaches, so name the
public base once and it wins everywhere:

<Snippet file="examples/server/mount.ts" region="callback-base-url" title="Behind an edge" />

Register that same callback URL with the provider's OAuth client or integration.
