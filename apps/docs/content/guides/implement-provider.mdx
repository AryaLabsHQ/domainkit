A provider is one value. Auth methods are optional cases, so a provider that only issues personal
tokens declares `token` and nothing else. Adding OAuth is one more case on the same definition.

## Declare the token fields once

`Provider.tokenAuth` takes the values the method needs as a `fields` schema. Secrets are
`Schema.RedactedFromValue(Schema.String)` and optional values use `Schema.optionalKey`.

That one declaration does three jobs: the connect form renders from it without knowing the
provider, `Connect.start` decodes the submitted values before `authenticate` runs, and
`Snapshot.providers[].methods[]` carries the field list to the browser.

`authenticate` receives the decoded record and returns the credential: the opaque `secret`, the
account `context` your `context` schema describes, and `expiresAt` (`null` when it does not expire).

## The session

`session(credential)` returns four operations bound to that credential.

| Operation               | Contract                                                                      |
| ----------------------- | ----------------------------------------------------------------------------- |
| `capabilities()`        | What the credential actually holds; DomainKit records it on the authorization |
| `listTargets()`         | Every zone the credential reaches, with the context that addresses it         |
| `resolveTarget(domain)` | `Resolved`, `SelectionRequired`, or `NotFound`                                |
| `dns(target)`           | `list`, `create`, `get`, `delete` inside one zone                             |

`Provider.resolveAmong(domain, targets)` implements the standard rule so an adapter usually does not
write it: the most specific zone wins, several matches at the same depth need a selection, none is
`NotFound`.

Report the zone's nameservers on a `Target` when the provider exposes them. `Connect.discover` uses
them to break a tie between two connections that both hold the zone.

`create` must return the provider's id for the new record. Cleanup deletes by that id, so an adapter
that cannot return one produces receipts nothing can clean up.

## Keep opaque records opaque

A record type DomainKit does not model becomes `DnsRecord.Opaque` with the provider's own payload.
Planning still sees it, refuses to overwrite it, and reports a conflict, so an adapter never has to
guess at a shape it cannot represent.

## Classify failures

Decode the response at the HTTP boundary and fail with the reason that tells a host what to do next.
Never let a raw response body or a credential reach a `DomainKit.Error`; a provider status or error
code belongs in `code`.

| Provider condition                   | Reason                |
| ------------------------------------ | --------------------- |
| Credential rejected                  | `Unauthenticated`     |
| Credential lacks the permission      | `Forbidden`           |
| Zone or record absent                | `NotFound`            |
| A conflicting record already exists  | `ProviderConflict`    |
| The operation is not supported there | `Unsupported`         |
| Rate limited or unavailable          | `ProviderUnavailable` |
| Anything else the provider refused   | `ProviderRejected`    |

## Version the stored context

`context` is persisted as an envelope tagged with `contextVersion`. Bump the version whenever the
schema changes, and add `migrateContext` to upgrade an older envelope. Without one, an older
envelope fails `Unsupported` instead of decoding into the wrong shape.

## Register it

```ts
DomainKit.layer({ providers: [porkbun] });
```

`Providers` rejects two definitions with the same id, and `Provider.make` rejects an id that is not
lowercase kebab-case, a definition with no auth method, and an empty `contextVersion`.

## Prove it

<Snippet file="examples/testing/conformance.ts" region="provider" title="Against a real account" />

The runner exercises create and read back, exact no-op, conflict, stale plan, and partial apply
through the same `Provision` and `Cleanup` services a host uses. It writes to a real zone, so point
it at one you own; every record it creates carries the prefix and is removed again.

## Adapting a Promise client

`Provider.fromAsync` wraps a Promise-shaped definition, for an adapter built on an existing SDK or
client. The lifecycle sees the same `Provider.Definition` either way.

The [provider contract](/docs/reference/providers) reference states the same rules without the
walkthrough.
