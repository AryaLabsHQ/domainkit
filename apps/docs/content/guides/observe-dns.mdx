`Verification.observe` is DomainKit's DNS check. Choose the source based on the question your product
needs to answer.

The snippets below are continuations of your provisioning flow. They assume `record` is the
requirement being checked, `zone` is the connected authoritative zone, and `provider` is the
server-side `DnsProvider` service for that connection.

## Observe public DNS

Public DNS is enabled by default:

```ts
import { Effect } from "effect";
import { Verification } from "domainkit";

const result = await Effect.runPromise(Verification.observe({ record }));
```

The default resolver pool asks Cloudflare and Google over DNS over HTTPS at the same time. The default
`AnyMatch` policy accepts one matching resolver.

## Observe the authoritative provider

Provider readback asks whether the connected account contains the desired record:

```ts
const result = await Verification.observe({
  provider: Verification.Provider.Enabled({ zone }),
  publicDns: Verification.PublicDns.Disabled(),
  record,
}).pipe(Effect.provideService(DnsProvider.Service, provider), Effect.runPromise);
```

This is useful after apply, but it does not prove that public resolvers can answer with the record.

## Require both sources

Enable both sources when your workflow requires provider state and public propagation:

```ts
const result = await Verification.observe({
  provider: Verification.Provider.Enabled({ zone }),
  publicDns: Verification.PublicDns.Enabled({}),
  record,
}).pipe(Effect.provideService(DnsProvider.Service, provider), Effect.runPromise);
```

The result is `Verified` only when every requested source matches.

## Handle every outcome

```ts
switch (result._tag) {
  case "Verified":
    break;
  case "Pending":
    break;
  case "Mismatch":
    break;
  case "Unavailable":
    break;
  case "NotObserved":
    break;
}
```

- `Pending` means a requested source has not observed the desired record yet.
- `Mismatch` means observed DNS differs from the requirement.
- `Unavailable` means the requested observation could not produce trustworthy evidence.
- `NotObserved` means no evidence source was requested.
- `Verified` means every requested source matched.

Do not turn `Unavailable` into `Pending`: a timeout and propagation delay need different product
responses.

## Choose a resolver policy

Provide a custom `DnsResolverPool.Service` when your reliability model needs:

- `AnyMatch` — one resolver match is sufficient;
- `AllMatch` — every configured resolver must match;
- `Quorum({ minimum })` — at least the selected number must match.

Each public-DNS result keeps the answer, no-data response, timeout, or failure from every resolver so
the host can explain disagreement.

## Keep product state in the host

DNS observation answers a DNS question. It does not replace certificates, email-provider readiness,
application checks, background polling, or your onboarding state. Map the tagged evidence into that
host-owned lifecycle.
