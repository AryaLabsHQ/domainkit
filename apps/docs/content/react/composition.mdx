`Domain.useFlow` returns everything a surface needs and renders nothing, so the markup is yours from
the first element. The [registry block](/components/registry/domain-flow) is one such surface, on
shadcn; this page is the shape of writing another.

## What the flow hands you

| Field                     | Carries                                                              |
| ------------------------- | -------------------------------------------------------------------- |
| `state`                   | What DomainKit has to say about the domain, as plain fields          |
| `connection`              | The connect controller: `connect`, `reuse`, `detach`, `disconnect`   |
| `provisioning`, `cleanup` | The plan, approve, apply machine for adding and for removing         |
| `verification`            | The observer, with the readiness it last read                        |
| `plan`                    | The plan still awaiting its apply, which is what the rows report     |
| `readiness`               | The last observation, which is what the rows report after an apply   |
| `capabilities`            | The groups the transport declares, so nothing offers a step it lacks |
| `requirements`, `domain`  | What the host asked for, and for which domain                        |

## One row's standing

`Records.statusOf` answers what a row has to say without the surface deciding: while a plan is
pending it is the operation the plan holds for that record, and once an apply has landed it is the
status the observers read back.

## The one action

`provisioning.approve()` authorizes the plan's digest and applies it in the same call. Name the
operation ids to approve part of a plan, which is how a blocked record is left out while the rest
goes in; approving a whole plan that holds a conflict is refused.

## Adding a domain

`Connect.useZones` lists every zone the workspace's accounts reach, and `Connect.useDomainField`
turns one text input into a combobox over them: it returns the props for the input, the listbox, and
each option, moves the highlight with the arrow keys, and completes on Tab or Enter while keeping
whatever subdomain was typed in front of the zone.

A domain outside every connected zone leaves the input a plain text field, because the customer will
add those records by hand. `onResolve` reports the account a value settles in, so a form submits the
domain and its connection together.

Connecting an account names no domain: what the customer grants is the account itself.
`Connect.describeMethods` arranges one provider's methods into the interactive ones a customer
clicks through and the ones that ask for credentials, so a surface asks for one decision at a time.

## Read-only

`readOnly` on `DomainKit.Root`, or on one `Domain.useFlow`, refuses every command that would change
the domain, in the controller rather than in your markup, and reports itself on
`flow.state.readOnly`. A surface reads it and says who may connect rather than rendering an empty
row.

<Snippet file="examples/react/read-only.tsx" region="hook" title="A surface that knows the mode" />

`DomainKit.useReadOnly()` answers for a component of your own, and `DomainKit.ReadOnly` narrows one
subtree without touching the rest of the page.
