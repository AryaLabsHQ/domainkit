DomainKit React turns the core lifecycle into ready-made flows and smaller parts. Start with the
complete `Domain.Flow`, use one focused flow, or build your own screen from models and parts. The
[integration levels guide](/docs/react/integration-levels) compares these choices and the work your
app still owns.

Install the React package with its peer dependencies and opt in to the default stylesheet:

```package-install
@domainkit/react domainkit effect@rc @effect/atom-react@rc react react-dom
```

```tsx
import { Domain, DomainKit } from "@domainkit/react";
import "@domainkit/react/styles.css";

export function DomainSetup() {
  return (
    <DomainKit.Root transport={transport}>
      <Domain.Flow domain="example.com" records={records} />
    </DomainKit.Root>
  );
}
```

`Domain.Flow` handles connection, plan review, apply, verification, cleanup, and removal of the
current domain grant. `DomainKit.Root` runs the host transport through Effect Atom. The package never
receives provider credentials in the browser; every operation goes through your authenticated
transport.

React 19 is required.

## Choose a flow or part

| Surface                          | Use it when                                              |
| -------------------------------- | -------------------------------------------------------- |
| `Domain.Flow`                    | You want the complete lifecycle in one component         |
| `Connection.Flow`                | You only need provider connection and reuse              |
| `Provisioning.Flow`              | Your product already owns the surrounding domain screen  |
| `Records.Table` / `Records.Card` | You want presentational DNS records without a transport  |
| Hooks and parts                  | Your design system owns structure and interaction chrome |

Server rendering is supported. Clipboard access, downloads, and navigation occur only from browser interactions.

The [component catalog](/components) has installation, examples, states, accessibility, and API
details for each component. These pages explain package-wide choices and the host transport.

## Keep the host boundary explicit

The React package owns the UI flows and client-side state. Your app still owns authentication,
authorization, saved attempts, secrets, provider credentials, and the server-side `Transport`
implementation. See
[Integrate with your host application](/docs/guides/host-integration) for the end-to-end boundary.
