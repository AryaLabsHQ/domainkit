`@domainkit/react` renders the whole custom-domain lifecycle over a transport your server owns.
Provider credentials never reach the browser: the transport calls the routes you mounted from
`domainkit/server`.

```package-install
@domainkit/react domainkit effect@rc react react-dom
```

React 19 is required. Install `domainkit` and `@domainkit/react` at the same release version.

`Domain.Flow` connects a provider, plans the DNS changes, takes the customer's approval or refusal,
applies the plan, observes the records, and cleans them up against the apply receipt. It renders
only the capability groups the transport declares.

Writing `Transport.fromFetch("/api/domainkit")` inline in JSX is fine: `DomainKit.Root` keeps the
transport's identity for the whole mount, so the controllers do not restart on every render.

## Three ways in

| Level       | You write                             | Reach for it when                                      |
| ----------- | ------------------------------------- | ------------------------------------------------------ |
| The flow    | `<Domain.Flow domain requirements />` | The product needs a working screen today               |
| Slots       | One or more slot render functions     | Most of the flow fits and one part is yours            |
| Controllers | `useController` and your own markup   | The lifecycle belongs inside a screen you already have |

[Composition](/docs/react/composition) covers slots, [controllers](/docs/react/controllers) the
hooks, and [presentation](/docs/react/presentation) the theme, messages, marks, and icons.

`onEvent` fires when a customer finishes something: `Connected`, `Applied`, `Cleaned`, `Declined`,
`Detached`, `Disconnected`, and `Failed`. A listener that throws cannot change the outcome of an
operation that already completed.

## Keeping the UI honest

Pass `revision` and bump it after a change the UI did not make, such as a webhook that disconnected
a provider. Every mounted domain re-inspects.

## Next.js

The package entry carries `"use client"`. A transport is an object of functions, so build it inside
a client module rather than passing one down from a server component.

## The member view

A customer who may read a domain but not change it gets `readOnly`. Status, records, and evidence
render; every control that would start a write is gone rather than disabled, because a dead button
is a worse answer than no button.

<Snippet file="examples/react/read-only.tsx" region="root" title="Read-only for the whole tree" />

<Snippet file="examples/react/read-only.tsx" region="per-domain" title="One domain among several" />

Capability gating is the other half and is unchanged: a group the transport never declares still
never renders. `readOnly` covers the authorization a transport cannot express, such as a member of
an organisation who reaches the same routes and would get a 403 from any write.

Observation stays available, because checking DNS reads the world rather than changing the domain.
Retrying does not: a flow that becomes read-only after a write failed keeps the failure on screen
and drops the retry.

## Where an interactive provider returns

<Snippet file="examples/react/domain-settings.tsx" region="return-to" title="Naming the return" />

`returnTo` defaults to the page the customer started from, read when they connect rather than when
the flow renders. Pass `null` to send none and leave the server's `defaultReturnTo` in charge.

## Styles

```ts
import "@domainkit/react/styles.css";
```

The stylesheet is opt-in and every colour in it is a `--domainkit-*` custom property, so a host that
imports it can still restyle everything through `theme`.

Every rule ships inside `@layer domainkit`, which sits below any unlayered rule. Your own stylesheet
wins without out-specifying a part selector, and a utility class lands where you put it.

Once your app uses layers of its own, name the order. A layer's priority is its position in that
list, and one you never declare lands wherever it first appears, so `domainkit` can end up under
Tailwind's preflight and the package's buttons render as bare text.
