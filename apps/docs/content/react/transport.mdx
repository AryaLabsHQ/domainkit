title: Transport
description: Implement the DomainKit React transport with authenticated app endpoints. Provider credentials and API clients stay on the server.

  title: Keep DNS provider credentials off the React client

`DomainKit.Root` receives a Promise-based `DomainKitTransport`. The shape is intentionally application-facing rather than a browser wrapper around provider APIs.

```ts
import type { Transport } from "@domainkit/react";

export const transport: Transport.DomainKitTransport = {
  connection: {
    inspect: (input) => api.connections.inspect(input),
    connect: (input) => api.connections.connect(input),
    reuse: (input) => api.connections.reuse(input),
    removeDomain: (input) => api.connections.removeDomain(input),
  },
  provisioning: {
    plan: (input) => api.provisioning.plan(input),
    apply: (input) => api.provisioning.apply(input),
  },
  verification: {
    observe: (input) => api.verification.observe(input),
  },
  cleanup: {
    plan: (input) => api.cleanup.plan(input),
    apply: (input) => api.cleanup.apply(input),
  },
};
```

```text
@domainkit/react
  -> authenticated host endpoint
  -> durable connection + receipt state
  -> domainkit or domainkit/effect
  -> Cloudflare / Vercel
```

Every outcome uses `_tag`, including failures and retry guidance. Decode untrusted request, database, and provider data at your server boundary before mapping it into these browser-safe wire types.

<Callout type="warning" title="No browser credentials">
  A token input may collect a credential, but submit it directly to your authenticated server
  endpoint. Never construct a Cloudflare or Vercel provider client in browser code.
</Callout>
