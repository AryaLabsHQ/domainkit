`DomainKit.Root` receives a `Layer<Transport.Service>`. Its controllers use Effect Atom to stop old
requests, ignore stale results, and clean up when the React subtree closes. The service is for your
app; it is not a browser wrapper around provider APIs.

The [host integration guide](/docs/guides/host-integration) shows where the transport belongs in a
complete browser, application server, and provider architecture.

```ts
import { Transport } from "domainkit";
import * as Layer from "effect/Layer";

const service = Transport.Service.of({
  connection: {
    inspect: (input) => api.connections.inspect(input),
    connect: (input) => api.connections.connect(input),
    attach: (input) => api.connections.attach(input),
    detach: (input) => api.connections.detach(input),
  },
  provisioning: {
    plan: (input) => api.provisioning.plan(input),
    apply: (input) => api.provisioning.apply(input),
  },
  verification: {
    observe: (input) => api.verification.observe(input),
  },
  cleanup: {
    plan: (input) => api.cleanup.plan(input),
    apply: (input) => api.cleanup.apply(input),
  },
});

export const transport = Layer.succeed(Transport.Service, service);
```

When an authenticated client already returns Promises, adapt it at that boundary instead of creating
a second React transport contract:

```ts
import { Transport } from "domainkit";

export const transport = Transport.layerFromAsync({
  connection: api.connections,
  provisioning: api.provisioning,
  verification: api.verification,
  cleanup: api.cleanup,
});
```

```text
@domainkit/react
  -> authenticated host endpoint
  -> durable connection + receipt state
  -> domainkit
  -> Cloudflare / Vercel
```

Successful outcomes use tagged models. Failures use `Transport.Failure` in the Effect error channel.
Check untrusted request, database, and provider data at your server boundary before mapping it into
these browser-safe types.

Custom UI can consume `Connection.useModel(domain)` with `useAtomValue(model.state)` and
`useAtomSet(model.command)`. Dispatch `Connection.Command.Connect`, `Attach`, `Detach`, and `Retry`;
the packaged controller and flow use the same atoms. A reusable connection contains its
credential-scoped provider connection and the discovered targets it can attach. Selecting a target
attaches that existing connection to the domain without reconnecting.

`ProviderTarget` is an exact account-and-zone choice. Keep discovery and selection on the server, and
return an unavailable or ambiguous target when the credential cannot produce one safe choice.
Integration authentication is separate from OAuth and should use
`AuthenticationMethod.Integration` when the provider supports it.

## Correlate browser operations with durable attempts

Treat every plan application as a server-side attempt. Save the plan and its digest before
returning it to the browser, then require the browser to submit that digest when it asks the server
to apply the plan.

```text
browser requests plan
  -> server plans and persists { attemptId, planDigest, plan }
  -> browser reviews plan
  -> browser submits { attemptId, planDigest }
  -> server authorizes and applies the persisted plan
  -> server stores the receipt
```

This keeps retries, approval decisions, and support investigations attached to one saved record
instead of trusting a plan that the browser can change.

## Use product-owned verification when needed

`Transport` exposes provider-backed operations. Public DNS verification is a separate product choice:
your server can use `Verification.observe` with public resolvers, expose an endpoint, and map its
result into product state without giving the browser resolver or provider credentials.

<Callout type="warning" title="No browser credentials">
  A token input may collect a credential, but submit it directly to your authenticated server
  endpoint. Never construct a Cloudflare or Vercel provider client in browser code.
</Callout>

See the [Transport reference](/docs/reference/transport) for every service method and
[Observe DNS](/docs/guides/observe-dns) for verification policy choices.
