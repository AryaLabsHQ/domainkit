| Export      | Carries                                                                          |
| ----------- | -------------------------------------------------------------------------------- |
| `PgStorage` | `layer(options)`, the `Storage.Service` implementation on the host's `SqlClient` |
| `capsule`   | The declaration itself, which `capsuledb emit` reads to write SQL                |
| `VERSION`   | The installed package version, read from the package manifest                    |

{/* reference-inventory:end */}

## Options

| Option           | Default     | Effect                                                                   |
| ---------------- | ----------- | ------------------------------------------------------------------------ |
| `prefix`         | `domainkit` | The table prefix. Part of the physical layout; fixed at the first deploy |
| `mode`           | `prepare`   | `prepare` migrates at boot; `assert` expects the host applied the SQL    |
| `registryPrefix` | `capsuledb` | CapsuleDB's own ledger prefix; must match `capsuledb emit --prefix`      |

<Snippet file="examples/storage/postgres.ts" region="wire" title="Installing the layer" />

The layer requires only `SqlClient`. Credentials arrive sealed, so Storage never needs `Custody` and
never handles plaintext.

## Tables

| Table                      | Key                               | Holds                                                             |
| -------------------------- | --------------------------------- | ----------------------------------------------------------------- |
| `domainkit_authorizations` | `id`                              | Provider grant, capabilities, revocation state, sealed credential |
| `domainkit_connections`    | `id`                              | The principal-facing handle over one authorization                |
| `domainkit_attachments`    | `id`, unique `(owner_id, domain)` | Domain, zone, provider target                                     |
| `domainkit_continuations`  | `id`                              | Interactive-flow state with a TTL                                 |
| `domainkit_attempts`       | `id`                              | Plan, approval, receipt, status, lease, failure                   |
| `domainkit_readiness`      | `(owner_id, domain)`              | Latest observation, per-requirement evidence, backoff             |

Every table carries `owner_id` and every query filters by the request's `Principal`, so a row
belonging to another tenant reads as absent. The package declares no foreign keys, to host tables
or between its own.

## Emitting the SQL

```sh
capsuledb emit \
  --module ./node_modules/@domainkit/capsuledb/dist/index.mjs \
  --export capsule \
  --dialect postgres \
  --out ./drizzle
```

That writes the ledger DDL, the capsule's migration, a readiness row, and a `capsuledb.emit.json`
index naming the files it owns. Apply them with your own pipeline, then boot in assert mode.

<Snippet file="examples/storage/postgres.ts" region="assert" title="Assert mode" />

`capsuledb check` compares an emitted folder against the current capsule in CI.

The migration is id `1`, name `create-storage`, under capsule id `domainkit.storage`.
