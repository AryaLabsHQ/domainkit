A provider is one `Provider.Definition` value. Auth methods are optional cases, so a provider that
only issues personal tokens declares `token` and nothing else. The definition drives the connection
routes, refresh, the UI method catalog, and rebuilding a session from stored context.

## The definition

| Field            | Purpose                                                                              |
| ---------------- | ------------------------------------------------------------------------------------ |
| `id`             | Lowercase kebab-case, stable, stored on every row                                    |
| `name`           | The display name a UI shows                                                          |
| `auth`           | Any of `token`, `oauth`, `integration`; at least one                                 |
| `context`        | The schema for the account and zone context stored on authorizations and attachments |
| `contextVersion` | The tag written into every stored context envelope, bumped with the schema           |
| `migrateContext` | Upgrades an envelope written under an older version; absent means `Unsupported`      |
| `session`        | A credential to a `Session`                                                          |

## The session

| Operation               | Contract                                                                      |
| ----------------------- | ----------------------------------------------------------------------------- |
| `capabilities()`        | What the credential actually holds; promoted onto the authorization           |
| `listTargets()`         | Every zone the credential reaches, with the identity needed to address it     |
| `resolveTarget(domain)` | `Resolved`, `SelectionRequired`, or `NotFound`; never chooses across accounts |
| `dns(target)`           | `list`, `create`, `get`, `delete` inside one zone                             |

`create` must return the provider's id for the new record. Cleanup deletes by that id, so a
provider that cannot return one cannot be cleaned up by receipt.

`Provider.resolveAmong(domain, targets)` implements the standard rule: the most specific zone wins,
several matches at the same depth need a selection, none is `NotFound`.

## Token methods

`Provider.tokenAuth` declares the values a method needs once, as a `fields` schema. Secrets are
`Schema.RedactedFromValue(Schema.String)` and optional values use `Schema.optionalKey`, so the
connect form renders from the definition and `Connect.start` decodes the values before the provider
sees them.

## Portable record types

Both first-party adapters support `A`, `AAAA`, `CAA`, `CNAME`, `MX`, `NS`, `SRV`, and `TXT`. A
provider record DomainKit cannot model is kept as `DnsRecord.Opaque` during reads, so planning sees
it, refuses to overwrite it, and reports a conflict instead.

## Classifying a failure

Decode the provider's response at the HTTP boundary and fail with the reason that tells a host what
to do next. Never let a raw response body or a credential reach a `DomainKit.Error`.

| Provider condition                   | Reason                |
| ------------------------------------ | --------------------- |
| Credential rejected                  | `Unauthenticated`     |
| Credential lacks the permission      | `Forbidden`           |
| Zone or record absent                | `NotFound`            |
| A conflicting record already exists  | `ProviderConflict`    |
| The operation is not supported there | `Unsupported`         |
| Rate limited or unavailable          | `ProviderUnavailable` |
| Anything else the provider refused   | `ProviderRejected`    |
