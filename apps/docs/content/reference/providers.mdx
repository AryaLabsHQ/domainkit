## Provider contract

`DnsProvider.Interface` is the provider capability used for planning, apply, delete, and provider
checks.

| Member         | Purpose                                                               |
| -------------- | --------------------------------------------------------------------- |
| `id`           | Stable provider identity embedded in plans and checked before apply.  |
| `listRecords`  | Read all records in an authoritative zone, including opaque records.  |
| `getRecord`    | Read one record by provider record ID.                                |
| `createRecord` | Create a normalized DomainKit record and return a stable provider ID. |
| `deleteRecord` | Delete a record by the ID captured in an application receipt.         |

Provider failures use `DnsProvider.Error` with the operation, provider ID, optional status/code,
reason, and optional retry delay. Keep the original cause for diagnostics, but do not send secrets or
raw provider responses to the browser.

`CreateResult.providerRecordId` may be `null` when a provider cannot return a record identifier.
Receipt-bound deletion requires a stable, non-null ID, so the conformance cases that read back and
clean up created records require adapters to return one for those writes.

Promise-first adapters can implement `DnsProvider.AsyncInterface` and use `fromAsync` or
`layerFromAsync`. `toAsync` adapts an environment-free Effect provider in the opposite direction.

## Bundled providers

`Cloudflare` and `Vercel` each group:

- OAuth or Integration authorization helpers;
- token-based constructors;
- account or team discovery;
- zone discovery; and
- a `DnsProvider` implementation.

The provider namespaces do not store OAuth state, credentials, connections, plans, or receipts. Your
host owns those stores and builds a provider service for each approved operation.

### Cloudflare

`Cloudflare` supports OAuth and API-token authentication, account discovery from an authorized
zone, zone discovery, and provider reconstruction from a stored non-secret account context plus a
host-held credential. `Cloudflare.Auth.refreshCredential` exchanges a host-held refresh token,
preserves or adopts refresh-token rotation, and returns the complete credential the host must
persist. The host owns refresh serialization and reconnect policy.

### Vercel

`Vercel` supports Integration authorization and token authentication, personal or team context,
zone discovery, and provider reconstruction from the stored context plus a host-held credential.

## Opaque records

An adapter must return unsupported provider records as `DnsRecord.Opaque` values instead of dropping
them. Planning keeps opaque records and avoids assumptions about data it cannot model. Deletion
targets only provider record IDs captured by a DomainKit receipt.

## Acceptance

Run the public `ProviderConformance` suite against a fresh isolated instance, then add adapter tests
for authentication, discovery, pagination, provider errors, rate limits, and live API behavior.
