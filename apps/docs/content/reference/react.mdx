```tsx
import { Domain, DomainKit } from "@domainkit/react";
import "@domainkit/react/styles.css";
```

The package entry carries `"use client"`. Namespaces mirror the core lifecycle.

{/* reference-inventory:start */}

## Namespaces

| Namespace    | Carries                                                                                                               |
| ------------ | --------------------------------------------------------------------------------------------------------------------- |
| `DomainKit`  | `Root`, `ReadOnly`, `useTransport`, `useCapabilities`, `useReadOnly`, `useDomainKit`                                  |
| `Domain`     | `Flow`, its slot props, and the slot defaults                                                                         |
| `Connect`    | `useController`, `Flow`, `Card`, `Dialog`, `Form`, `Prompt`, `Status`, `Outcome`, `Root`                              |
| `Outcome`    | `Root`, `Header`, `Media`, `Title`, `Description`, `Content`, `Composition`, `useOutcome`                             |
| `Provision`  | `useController`, `Flow`, `Actions`, `Dialog`, `Status`, `Outcome`, `Root`, `State`                                    |
| `Cleanup`    | The same set over a plan built from an apply receipt                                                                  |
| `Verify`     | `useController`, `Status`, `Evidence`, `ObserveAction`, `Outcome`, `Root`, `State`                                    |
| `Records`    | `Table`, `Card`, `ZoneFile`, `CopyValue`, `Status`, the table leaf parts, `identity`, `requirementsKey`, `toZoneFile` |
| `Operations` | `List`, `Item`, and the leaf parts one plan operation renders as                                                      |
| `Provider`   | `Mark`, `Marks`, and the provider `Descriptor` the snapshot carries                                                   |
| `Messages`   | `Catalog`, `english`, `merge`, and `failure(error, catalog)`                                                          |
| `Theme`      | The `Theme` shape and `toStyle`, over the `--domainkit-*` custom properties                                           |
| `Testing`    | `transport`, re-exported from `domainkit/testing` for UI tests                                                        |

## Top-level exports

| Export         | Carries                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------- |
| `Event`        | What a customer finished doing: `Connected`, `Applied`, `Cleaned`, `Declined`, `Failed`, `Detached`, `Disconnected` |
| `Listener`     | The `onEvent` signature `DomainKit.Root` takes                                                                      |
| `Failure`      | The failed member every controller state shares, carrying the `DomainKit.Error`                                     |
| `defaultIcons` | The built-in icon set                                                                                               |
| `useIcons`     | The icons in context, for a part you render yourself                                                                |
| `Icons`        | The icon slot names a host may override                                                                             |

{/* reference-inventory:end */}

`ClassName`, `Style`, and `PartProps` are the composition types every rendered part accepts: the
element's own props, a state-aware `className` and `style`, and Base UI's `render` for replacing
the element outright.

## Controllers

Each takes one options object and returns a controller whose `state` is a tagged union.

| Hook                      | Options                                | State tags                                                                                                       |
| ------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `Connect.useController`   | `{ domain, returnTo? }`                | `Loading`, `Disconnected`, `Connected`, `Reconnect`, `Submitting`, `Redirecting`, `SelectionRequired`, `Failure` |
| `Provision.useController` | `{ domain, requirements, onApplied? }` | `Idle`, `Planning`, `Planned`, `Approving`, `Applying`, `Applied`, `Rejecting`, `Rejected`, `Failure`            |
| `Cleanup.useController`   | `{ domain, receiptId?, onCleaned? }`   | The same set                                                                                                     |
| `Verify.useController`    | `{ domain, polling?, requirements? }`  | `Idle`, `Observing`, `Observed`, `Failure`                                                                       |

## Slots

`Domain.Flow` renders four slots, each with a default and no layout container of its own.

| Slot           | Receives                                        | Default                                                    |
| -------------- | ----------------------------------------------- | ---------------------------------------------------------- |
| `connection`   | `{ controller, domain }`                        | `Connect.Card` once connected, `Connect.Dialog` until then |
| `records`      | `{ records, readiness, controller, domain }`    | `Records.Table`                                            |
| `verification` | `{ controller, domain }`                        | `Verify.Status` with per-requirement evidence              |
| `actions`      | `{ connection, provisioning, cleanup, domain }` | Review changes, Approve, Decline, Remove records           |

<Snippet file="examples/react/slots.tsx" region="one-slot" title="Replacing one slot" />

`Domain.Flow` also takes `returnTo` for the connection it owns, and `readOnly` for one domain among
several.

## Read-only

`readOnly` renders the state without the controls that change it. A write surface is removed rather
than disabled, so connect, detach, disconnect, review, approve, decline, cleanup, and every `retry`
disappear. Re-inspecting and observing stay, because both only read.

| Export                  | Answers                                                       |
| ----------------------- | ------------------------------------------------------------- |
| `DomainKit.useReadOnly` | Whether this part may offer a control that changes the domain |
| `DomainKit.ReadOnly`    | Narrows one subtree, overriding the root for its children     |

<Snippet file="examples/react/read-only.tsx" region="hook" title="Reading the mode" />

It is not capability gating. A group the transport never declares still never renders; `readOnly`
covers the authorization a transport cannot express, such as a member who reaches the same routes
and would get a 403 from any write. Where a connect control would be, the catalog's `notConnected`
sentence takes its place.

## Styles

Every rule in `@domainkit/react/styles.css` ships inside `@layer domainkit`, which sits below any
unlayered rule, so a host's own CSS wins without out-specifying a part selector.

A host that uses layers names the order itself. `domainkit` belongs after `base`, because a layer
sorted under Tailwind's preflight loses the package's buttons to the reset, and before `utilities`,
so a utility class still wins.
