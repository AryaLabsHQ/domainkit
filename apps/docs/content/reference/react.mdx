```tsx
import { Domain, DomainKit } from "@domainkit/react";
```

The package entry carries `"use client"`. It exports hooks and helpers and renders no element of its
own; the styled composition is the [registry](/components/registry).

## Namespaces

| Namespace   | Carries                                                                                                                                                                                                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DomainKit` | `Root`, `ReadOnly`, `useDomainKit`, `useTransport`, `useMessages`, `useCapabilities`, `useReadOnly`                                                                                                                                                                                               |
| `Domain`    | `useFlow`, and the `Flow` and `FlowState` shapes it returns                                                                                                                                                                                                                                       |
| `Connect`   | `useController`, `useZones`, `useAccounts`, `useDomainField`, `describeMethods`, `rejectedField`, `attempted`, `offering`, `holdsConnection`, `reconnect`, `hostProvider`, `providerOf`, `displayName`, `reusableConnections`, `answeredInPlace`, `placementOf`, `suggestionsFor`, `completionOf` |
| `Provision` | `useController`, `State`, `pendingPlan`, `planOf`                                                                                                                                                                                                                                                 |
| `Cleanup`   | The same set over a plan built from an apply receipt                                                                                                                                                                                                                                              |
| `Verify`    | `useController`, `State`, `valuesOf`, and the readiness shapes it reports                                                                                                                                                                                                                         |
| `Records`   | `statusOf`, `useCopy`, `copyText`, `toZoneFile`, `downloadZoneFile`, `identity`, `requirementsKey`                                                                                                                                                                                                |
| `Outcome`   | `describe(error, catalog)` and `useDescribe()`, which binds the catalog the root holds                                                                                                                                                                                                            |

| `Testing`   | `transport`, re-exported from `domainkit/testing` for UI tests                                                                                                                                                                                                                                    |

| Export     | Carries                                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------------------------- |
| `Event`    | What a customer finished doing: `Connected`, `Applied`, `Cleaned`, `Declined`, `Failed`, `Detached`, `Disconnected` |
| `Listener` | The `onEvent` signature `DomainKit.Root` takes                                                                      |

## The flow

`Domain.useFlow({ domain, requirements, connect?, onApplied?, onCleaned?, returnTo?, readOnly? })`
runs the four controllers together, attaches nothing the customer has not granted, and plans as soon
as the domain is attached with nothing applied. An apply observes the domain again, and an applied
domain plans again once an observation made after the apply reads a record back missing or wrong, so
records deleted at the provider are offered again.

| Field                     | Carries                                                              |
| ------------------------- | -------------------------------------------------------------------- |
| `state`                   | `FlowState`, below                                                   |
| `connection`              | The connect controller                                               |
| `provisioning`, `cleanup` | The plan, approve, apply machine for adding and for removing         |
| `verification`            | The observer, with the readiness it last read                        |
| `plan`                    | The plan still awaiting its apply, which is what the rows report     |
| `readiness`               | The last observation, which is what the rows report after an apply   |
| `capabilities`            | The groups the transport declares, so nothing offers a step it lacks |
| `requirements`, `domain`  | What the host asked for, and for which domain                        |
| `invitation`              | What the flow was told to offer when discovery names no host         |

## Controllers

Each takes one options object and returns a controller whose `state` is a tagged union.

| Hook                      | Options                                | State tags                                                                                                       |
| ------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `Connect.useController`   | `{ domain, returnTo? }`                | `Loading`, `Disconnected`, `Connected`, `Reconnect`, `Submitting`, `Redirecting`, `SelectionRequired`, `Failure` |
| `Connect.useZones`        | `{ provider? }`                        | `Loading`, `Ready`, `Failure`                                                                                    |
| `Connect.useAccounts`     | `{ returnTo? }`                        | `Loading`, `Ready`, `Submitting`, `Redirecting`, `Failure`                                                       |
| `Provision.useController` | `{ domain, requirements, onApplied? }` | `Idle`, `Planning`, `Planned`, `Approving`, `Applying`, `Applied`, `Rejecting`, `Rejected`, `Failure`            |
| `Cleanup.useController`   | `{ domain, receiptId?, onCleaned? }`   | The same set                                                                                                     |
| `Verify.useController`    | `{ domain, polling?, requirements? }`  | `Idle`, `Observing`, `Observed`, `Failure`                                                                       |

## Flow state

| Field                    | Carries                                                                       |
| ------------------------ | ----------------------------------------------------------------------------- |
| `connection`             | `Connect.State["_tag"]`                                                       |
| `provisioning`           | `Provision.State["_tag"]`                                                     |
| `connected` / `offering` | Whether DomainKit holds a connection, and whether it is offering one          |
| `provider`               | Who holds the connection, or whose nameservers serve the zone                 |
| `label`                  | The account the records go to, from the attachment; `null` until there is one |
| `receiptId` / `applied`  | The apply receipt this domain produced, and whether there is one              |
| `readOnly`               | The customer may read this domain but not write to it                         |

## Read-only

`readOnly` refuses every command that changes the domain: connect, attach, detach, disconnect,
plan, approve, decline, apply, and every `retry`. Re-inspecting and observing stay, because both
only read. The refusal is in the controller, not in the markup, so a control a host renders anyway
cannot reach the transport. Every controller takes `readOnly` as an option, which is how
`Domain.useFlow` passes its own flag to the four it runs.

| Export                  | Answers                                                          |
| ----------------------- | ---------------------------------------------------------------- |
| `DomainKit.useReadOnly` | Whether this surface may offer a control that changes the domain |
| `DomainKit.ReadOnly`    | Narrows one subtree, overriding the root for its children        |

<Snippet file="examples/react/read-only.tsx" region="hook" title="Reading the mode" />

It is not capability gating. A group the transport never declares is absent from
`flow.capabilities`; `readOnly` covers the authorization a transport cannot express, such as a
member who reaches the same routes and would get a 403 from any write. Where a connect control would
be, the catalog's `administratorConnects(provider)` sentence takes its place.

## Words

`Messages.Catalog` holds every user-visible string, including a title and a description per
`DomainKit.Error` reason. `Outcome.useDescribe()` binds the merged catalog and returns that pair for
one error; `Outcome.describe(error, catalog, context?)` is the same answer without a React context.
