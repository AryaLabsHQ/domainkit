## Endpoints

`Server.group` is one `HttpApiGroup` with eighteen endpoints. It declares no prefix of its own, so
`Server.group.prefix("/internal/dns")` or a router mount moves every route at once and the OAuth
callback URL follows the mount.

| Method   | Path                                       | Endpoint      | Answers                  |
| -------- | ------------------------------------------ | ------------- | ------------------------ |
| `GET`    | `/domains/:domain`                         | `inspect`     | `Snapshot`               |
| `GET`    | `/domains/:domain/discovery`               | `discover`    | `Discovery`              |
| `GET`    | `/zones`                                   | `zones`       | `Zones`                  |
| `POST`   | `/connections`                             | `start`       | `Started`                |
| `GET`    | `/callback/:provider`                      | `callback`    | `302` to the return path |
| `POST`   | `/connections/:connectionId/reconnections` | `reconnect`   | `Started`                |
| `POST`   | `/connections/:connectionId/attachments`   | `attach`      | `Started`                |
| `DELETE` | `/attachments/:attachmentId`               | `detach`      | Empty                    |
| `DELETE` | `/connections/:connectionId`               | `disconnect`  | Empty                    |
| `POST`   | `/domains/:domain/plans`                   | `createPlan`  | `Plan.Model`             |
| `POST`   | `/plans/:planId/approvals`                 | `approve`     | `Approval.Model`         |
| `POST`   | `/plans/:planId/rejections`                | `reject`      | `Attempt`                |
| `POST`   | `/approvals/:approvalId/apply`             | `apply`       | `Receipt.Model`          |
| `GET`    | `/plans/:planId`                           | `plan`        | `Attempt`                |
| `GET`    | `/receipts/:receiptId`                     | `receipt`     | `Receipt.Model`          |
| `POST`   | `/domains/:domain/observations`            | `observe`     | `Readiness`              |
| `GET`    | `/domains/:domain/readiness`               | `readiness`   | `Readiness \| null`      |
| `POST`   | `/receipts/:receiptId/cleanup-plans`       | `cleanupPlan` | `Plan.Model`             |

Approve, reject, and apply serve both provisioning and cleanup: the stored attempt knows its kind.

`start` takes an optional `domain`. Without one it connects the account alone and answers
`Connected` with the connection it made and no snapshot, which is how a customer grants an account
before they have named a domain in it. `zones` lists every zone those accounts reach, ordered by
zone, and marks a connection whose credential the provider turned down as `reconnect` beside the
zones that did come back. `?provider=` narrows it to one provider's connections. `reconnect` proves the connection's own
provider again and replaces the credential behind it, keeping the connection and every domain
attached to it; starting instead would mint a second account and leave the domains on the one the
provider turned down.

## Identity

`Server.Identity` is the only service a host implements. Everything else comes from
`DomainKit.layer` plus `Storage`.

| Member      | Required | Runs                                                                   |
| ----------- | -------- | ---------------------------------------------------------------------- |
| `principal` | yes      | On every request, before the handler, to derive `{ ownerId, actorId }` |
| `authorize` | no       | After `principal`, with the `EndpointName` of the route being served   |

<Snippet file="examples/server/mount.ts" region="identity" title="The Identity layer" />

Without `authorize`, every authenticated principal reaches every route, which is right for a host
whose own middleware already gates the mount. Implement it to split reads from writes, and fail
with the `Forbidden` reason for the 403 a UI expects.

<Snippet file="examples/server/mount.ts" region="authorize" title="Per-route authorization" />

`Server.EndpointName` is derived from the group, so it is exactly the endpoint identifiers in the
table above and a new route is a type error in an exhaustive host check rather than a silent gap.

### The callback resolves identity the other way round

`/callback/:provider` is the one route that knows something about the request before it knows who
made it. It is a top-level navigation the provider sends the browser on, carrying a `state` the
provider echoed back and whatever credential the browser attaches by itself, so ambient host state
is the wrong authority on whose connection it finishes.

So the handler reads the flow's own record first — owner, actor, provider, and expiry, never the
payload, and a read rather than a spend — and passes it to `principal` as a second argument:

```ts
interface IdentityContext {
  readonly endpoint: EndpointName;
  readonly continuation: Storage.ContinuationHeader;
}
```

`context` is optional and present on the callback alone, so a host that takes one argument keeps
compiling. Take it when one session holds several tenants and the callback has to land on the one
the flow belongs to.

<Snippet
  file="examples/server/mount.ts"
  region="callback-identity"
  title="Identity on the callback"
/>

The doctrine that a request never names its own `ownerId` is intact. `context.continuation` is
DomainKit's durable record of the flow, written when the connection started, and the `state` in the
query string only points at it.

DomainKit then checks the principal you return against that record itself, rather than trusting you
to: the owner and the actor must both match the session that started the flow, and the recorded
provider must match the route. A callback that matches no flow, one that has expired, one presented
at another provider's route, and one presented by a session that did not start it are all the same
`InvalidInput` refusal with the same text, and the host authenticates before any of them, so
neither the status nor the message tells a caller holding a leaked `state` whether it names a live
flow. The flow is left unspent, so the person who started it can still finish it.

## Mounting

<Snippet file="examples/server/mount.ts" region="mount" title="Mounting the group" />

`Server.layer(api, options)` builds the handlers. `Server.api` is the same group as a standalone
`HttpApi`, so `OpenApi.fromApi(Server.api)` documents it.

| Option            | Effect                                                                                                                                                                                               |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `callbackBaseUrl` | The origin and mount path the provider redirects back to. Set it behind an edge that rewrites `Host`; otherwise the callback follows the request's own origin and the prefix the group is mounted at |
| `defaultReturnTo` | Where an interactive flow lands when the continuation carries no `returnTo`                                                                                                                          |
| `prefix`          | `toWebHandler` only: mount every route under this path                                                                                                                                               |

## Wire schemas

The client and `@domainkit/react` decode these, so the three cannot drift.

| Schema             | Shape                                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `Snapshot`         | Domain, attachment, connection, provider, status, reusable connections, provider catalog                                       |
| `Attachment`       | The attachment's `id` and the zone `label` the provider gave when it was created                                               |
| `Zones`            | Every zone the principal's connections reach, how each connection stands with the account label the provider gave, the catalog |
| `Started`          | `Connected`, `Redirect`, or `SelectionRequired`                                                                                |
| `Discovery`        | `DiscoveryResolved`, `DiscoverySelectionRequired`, or `DiscoveryNotFound`                                                      |
| `Method`           | `Token`, `OAuth`, or `Integration`                                                                                             |
| `MethodDescriptor` | A method's `kind`, `label`, `docsUrl`, and token `Field` list                                                                  |
| `Attempt`          | `plan`, `status`, `approval`, `receipt`, `rejection`                                                                           |
| `ObservePayload`   | The `requirements` to observe, or nothing to use the attachment's receipt                                                      |
| `Readiness`        | `Verify.Readiness` with timestamps as ISO strings; each requirement carries its `key`                                          |

## Failures

A failure crosses the wire as the `DomainKit.Error` value with the status its reason derives, so a
`Conflict` is a 409 carrying the conflicting operations. See
[failure reasons](/docs/core/errors) for the whole table.
