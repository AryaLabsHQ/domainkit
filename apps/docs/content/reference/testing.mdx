Import test support from `domainkit/testing`. This public entry point is for tests, examples, local
development, and provider checks.

{/* reference-inventory:start */}

| Namespace                         | Purpose                                                                    |
| --------------------------------- | -------------------------------------------------------------------------- |
| `InMemoryDnsProvider`             | Stateful DNS provider for planning, apply, delete, and verification tests. |
| `InMemoryDnsResolver`             | Resolver with controlled answers and failures.                             |
| `InMemoryManagedDnsConnections`   | In-process saved connection store for lifecycle tests.                     |
| `InMemoryConnectionContinuations` | In-process continuation store for connection flows.                        |
| `ProviderConformance`             | Shared test suite for any `DnsProvider` implementation.                    |

{/* reference-inventory:end */}

## Test a lifecycle without credentials

```ts
import { DnsRecord, DomainName, Provisioning } from "domainkit";
import { InMemoryDnsProvider } from "domainkit/testing";
import { Effect } from "effect";

const program = Provisioning.create({
  requirements: [
    DnsRecord.Cname({
      metadata: { ownership: "customer", provenance: "test", purpose: "routing" },
      name: DomainName.parse("app.example.com"),
      policy: "exclusive",
      target: DomainName.parse("tenant.example.net"),
      ttl: 300,
    }),
  ],
  target: Provisioning.Target.ExactZone({ zone: "example.com" }),
}).pipe(Effect.provide(InMemoryDnsProvider.layer()));
```

The executable [quickstart](/docs/quickstart) follows this path through plan, approval, apply, and a
second plan that makes no changes.

## Validate a provider adapter

Run `ProviderConformance` against a fresh isolated provider instance. The suite checks create,
readback and cleanup, exact no-op, conflict without mutation, stale-plan rejection, and partial
apply cleanup. Add
provider-specific tests for authentication, discovery, pagination, rate limits, and live API
behavior; the shared suite cannot prove those concerns.

See [Implement a DNS provider](/docs/guides/implement-provider) for the full acceptance boundary.
